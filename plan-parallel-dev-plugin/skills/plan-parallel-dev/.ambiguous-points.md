# 曖昧な指示の一覧

以下の箇所について、修正の要否や修正方針をコメントしてください。

---

## 1. 「待機」の仕組みが不明確

**箇所**: SKILL.md:416, 434, worktree-guide.md:411, 423

```
- 依存タスクが未完了なら待機: マージ担当からの通知を待つ
- マージ担当が依存タスクの完了を通知するまで待機
```

**問題**: 作業用 claude はセッション終了後「待機」できない。実際はマージ担当が依存タスクマージ後に再度 `tmux split-window` で起動する仕組みだが、それが明記されていない

**対応**: そもそも依存タスクが終わっていない場合、その作業用 Claude は起動させないので、このような待機はそもそも起こりません。削除していい説明です。

---

## 2. 「伝達」の方法が不明確

**箇所**: SKILL.md:429

```
回答を作業用 claude に伝達する
```

**問題**: 作業用 claude へどうやって伝達するか不明。実際は issues/ にファイルを書いて、作業用 claude を再起動するのか？

**対応**:claude は起動しっぱなしなので、tmux send-keys で点辰しましょう。また、マージが終わって正しかった場合は、その CTRL+C を二回送ることで作業用 claude を終了させてください。

---

## 3. 「依存元タスクに通知」の方法が不明確

**箇所**: SKILL.md:378

```
# - 依存元タスクに通知
```

**問題**: 具体的にどうやって通知するか不明。タスク指示書に追記？再起動？

**対応**: この記述は決していいです。次のタスクを起動することで通知を兼ねています。また、このブロックがコメントアウトされてるのは良くないですね。

---

## 4. `{test-command}` の定義場所が不明

**箇所**: 多数（SKILL.md:362, 507, merge-coordinator.md:233, 390 など）

**問題**: テストコマンドがプレースホルダーのままで、どこで定義・設定されるか不明。計画作成時に確認すべき項目として advanced-features.md:128 に記載があるが、SKILL.md のワークフローには反映されていない

**対応**:　テストコマンドは不定なので、プレースホルダーというよりはコメントで「ユーザーの指示によりここにテストコマンドを入れる場合もあり」と書くのが良いです。

---

## 5. コンフリクト判断基準が曖昧

**箇所**: SKILL.md:428

```
軽微なら自分で解決、複雑なら作業用 claude に依頼
```

**問題**: 「軽微」「複雑」の基準が不明

**対応**: 全てマージ担当が自分で解決します。（作業者は全ての事情を知らないので）

---

## 6. 「0.5〜2 日程度の作業単位」

**箇所**: SKILL.md:51

```
粒度: 0.5〜2日程度の作業単位
```

**問題**: claude が実行する作業に「日」は適切な単位か？人間の作業時間感覚になっている

**対応**: 人間相当の時間で考えることで作業を分けるという意味で、今はこれでいいと思いますが、無限に働いたり無限の複雑度をあつかえる AI ならよりよい案は何かありますか？いくつか案をあげてください。

---

## 7. モード A/B の選択基準が曖昧

**箇所**: SKILL.md:15-38

**問題**: 「新規プロジェクトや大規模機能開発」「既存プロジェクトへのバグ修正・機能追加」の境界が曖昧。中規模の機能追加はどちらを使うべきか？

**対応**: すでに機能が実装されている場合は B です。まだ最初の uv init や React の初期化だけの場合は A です。中規模の機能追加の場合は、B ですが複数の作業者を起動したほうがいいでしょうね。またその場合 A と同様に並列作業計画書を作ってマージ担当を設けるのもいいでしょう。

## 8. 「必要に応じて」の判断基準が不明

```
必要に応じて新規 worktree/ブランチを作成
以下の詳細ガイドは必要に応じて参照
```

**問題**: どういう条件で必要になるか不明

**対応**: 453 は削除、405 はそれこそ場合によるのでこのまま残しましょう。

---

## 9. 計画書作成後の「ユーザーに直接伝える」

**箇所**: SKILL.md:71

```
計画書の内容をユーザーに直接伝える
```

**問題**: 何を伝えるべきか、どの程度の詳細さで伝えるべきか不明

**対応**: これからどんな順でどれぐらいの並列度で何をするかを列挙する。一部は表なども使う。

---

## 10. テスト環境の設定方法が分散

**箇所**: testing-guide.md, worktree-guide.md, env-local-template.md

**問題**: `.env` コピーと `.env.local` の関係、本番同等テストの設定方法が複数ファイルに分散しており、全体像が把握しづらい

**対応**: .env.local は存在しない場合もありますね省いてください。本番同等テストはちょっと後で相談しましょう。
