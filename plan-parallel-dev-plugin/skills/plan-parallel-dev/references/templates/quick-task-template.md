# クイックタスク指示書テンプレート

クイックタスクモード（モード B）で使用する簡易タスク指示書のテンプレート。
初期並列開発モード（モード A）の詳細なタスク指示書とは異なり、即座に作業を開始するための最小限の情報を記載する。

ファイル名: `.parallel-dev/tasks/{task-name}.md`

---

## テンプレート

```markdown
# クイックタスク: {task-name}

## 基本情報

| 項目 | 内容 |
|------|------|
| 依頼内容 | {ユーザーからの依頼を要約} |
| ブランチ | `{fix/feature}/{task-name}` |
| worktree | `worktree/{task-name}/` |
| ベースブランチ | `{main または指定ブランチ}` |
| 作成日時 | {YYYY-MM-DD HH:MM} |
| ステータス | 作業中 |

---

## 実行コンテキスト

このタスクはマージ担当（または依頼元 Claude）から tmux 経由で起動される。
作業ディレクトリ: `worktree/{task-name}/`

**環境変数 `PROJECT_ROOT`**: tmux 起動時に渡されるプロジェクトルートへの絶対パス。
`.done` ファイルは `$PROJECT_ROOT/.parallel-dev-signals/` に作成する。

---

## 依頼内容

{ユーザーからの依頼内容をそのまま記載}

### 補足情報（あれば）

- {関連するファイルパス}
- {参考になる既存実装}
- {注意点・制約}

---

## 作業手順

1. 依頼内容を理解し、関連するファイルを特定
2. 必要な修正を実装
3. ローカルで動作確認
4. `.done` ファイルを作成してセッション終了

---

## 完了時

実装が完了したら、以下のコマンドで完了報告を作成:

```bash
cat > $PROJECT_ROOT/.parallel-dev-signals/{task-name}.done << 'EOF'
【完了報告】{task-name}

## 実装内容
- {実装した内容を箇条書きで}
- {変更したファイル一覧}

## 動作確認
ローカルでの動作確認: OK / NG

## テスト結果（テストを実行した場合）
{テスト結果}

## 備考
{その他の情報・注意点}
EOF
```

---

## 問題発生時

問題が発生した場合は `.parallel-dev-issues/{task-name}.md` に記録:

```bash
cat > $PROJECT_ROOT/.parallel-dev-issues/{task-name}.md << 'EOF'
【問題報告】{task-name}

## 状況
{何が起きたか}

## エラー内容
{エラーメッセージ}

## 試した対応
- {試したこと1}
- {試したこと2}

## 必要な対応
{どうすれば解決できそうか}
EOF
```

---

## ルール

- **コミットしない**: コードを書くだけ。コミットはマージ担当が行う
- **プッシュしない**: リモートへのプッシュもマージ担当が行う
- **UI 仕様は確認**: UI の見た目に関する決定は勝手に行わず、確認依頼を出す
- **完了したらセッション終了**: `.done` ファイル作成後、作業完了

---

## 参考資料

- 関連ファイル: {パス}
- 類似実装: {パス}
```

---

## 記入ガイド

### タスク名の命名規則

タスク名は kebab-case で記述し、作業内容を簡潔に表す:

**バグ修正の場合:**
- `fix-login-validation`
- `fix-header-overflow`
- `fix-api-timeout`

**機能追加の場合:**
- `add-logout-button`
- `add-user-avatar`
- `feature-dark-mode`

**改善・リファクタリングの場合:**
- `improve-search-performance`
- `refactor-auth-module`
- `update-dependencies`

### ブランチプレフィックス

| 作業種類 | プレフィックス | 例 |
|----------|---------------|-----|
| バグ修正 | `fix/` | `fix/login-validation` |
| 機能追加 | `feature/` | `feature/dark-mode` |
| 改善 | `improve/` | `improve/search-perf` |
| リファクタリング | `refactor/` | `refactor/auth` |
| ドキュメント | `docs/` | `docs/api-guide` |

### ステータスの遷移

```
作業中 → 完了（.done 作成）→ マージ済
         ↓
       問題発生（.md 作成）→ 対応中 → 再開
```

---

## 初期並列開発（モード A）との違い

| 観点 | モード A（詳細タスク指示書） | モード B（クイックタスク） |
|------|--------------------------|-------------------------|
| 情報量 | 詳細な仕様・API定義・依存関係 | 依頼内容と最低限の情報 |
| 作成タイミング | 計画段階で事前作成 | 依頼を受けて即座に生成 |
| 依存関係 | 明示的に記載 | 基本的に単独タスク |
| Phase 分離 | 対応 | 非対応（シンプルな単発タスク向け） |
| マージ先 | 統合ブランチ | main または指定ブランチ |

## 使用例

### 例1: バグ修正

```markdown
# クイックタスク: fix-login-validation

## 基本情報

| 項目 | 内容 |
|------|------|
| 依頼内容 | ログイン画面でメールアドレスのバリデーションが効いていない問題を修正 |
| ブランチ | `fix/fix-login-validation` |
| worktree | `worktree/fix-login-validation/` |
| ベースブランチ | `main` |
| 作成日時 | 2024-01-15 10:30 |
| ステータス | 作業中 |

## 依頼内容

ログイン画面でメールアドレスのバリデーションが効いていない。
不正なメールアドレス（例: "test@"）でも送信できてしまう。

### 補足情報

- ログインフォーム: `src/components/auth/LoginForm.tsx`
- バリデーション: `src/lib/validation.ts`
```

### 例2: 機能追加

```markdown
# クイックタスク: add-logout-button

## 基本情報

| 項目 | 内容 |
|------|------|
| 依頼内容 | ヘッダーにログアウトボタンを追加 |
| ブランチ | `feature/add-logout-button` |
| worktree | `worktree/add-logout-button/` |
| ベースブランチ | `main` |
| 作成日時 | 2024-01-15 11:00 |
| ステータス | 作業中 |

## 依頼内容

ヘッダーの右上にログアウトボタンを追加してほしい。
クリックしたらセッションをクリアして `/login` にリダイレクトする。

### 補足情報

- ヘッダーコンポーネント: `src/components/layout/Header.tsx`
- 認証関連: `src/lib/auth.ts`
- ログインページ: `src/pages/login.tsx`
```
