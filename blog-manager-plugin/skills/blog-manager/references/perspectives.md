# Perspectives (観点テンプレート)

記事の「観点」を定義するテンプレート集です。

## Purpose

- 記事のトーン・スタイルを統一
- よく使う観点を再利用可能にする
- 素材（ideas/）とは独立して管理

---

## Standard Templates

ブログプロジェクトの `perspectives/` ディレクトリに以下のテンプレートを配置:

### showcase.md - 製品・ツール紹介

```yaml
---
name: showcase
description: "製品・ツールをわかりやすく紹介して使ってもらう"
---

# Showcase スタイル

## トーン
- 熱意を込めつつ、押し付けがましくない
- 「これは便利！」という感動を共有する
- 読者に「試してみたい」と思わせる

## 構成のポイント
- 最初に「何ができるか」を見せる（GIF/スクリーンショット）
- インストールは最短で（1-3コマンド）
- 実際の使用例を多めに
- CTA（スターして、試して）を明確に

## 使う表現
- 「〜できます」「〜が可能です」
- 「試してみてください」
- 「フィードバックお待ちしています」

## 避けること
- 技術的な実装詳細に深入りしない
- 長すぎる前置き
- 自慢っぽい表現
```

### personal.md - 個人的な考え・開発記録

```yaml
---
name: personal
description: "個人的な考えや開発記録を控えめに共有"
---

# Personal スタイル

## トーン
- 控えめで謙虚
- 「私はこう考えている」という提案ベース
- 読者に考える余地を残す

## 構成のポイント
- 読者の課題・悩みへの共感から始める（問題提起）
- 背景や動機から始める
- 試行錯誤のプロセスを含める
- 実例は具体的なエピソードとして語る（抽象的な説明ではなく）
- 図やコード例で視覚的にわかりやすく
- 結論を押し付けない
- 「参考になれば」というスタンス

## 使う表現
- 「個人的には〜と思います」
- 「一つのアプローチとして」
- 「ご意見いただければ」
- 「まだ試行錯誤中ですが」
- 「私がやっているのは〜という手法です」
- 「重要なのは〜」（要点の強調、ただし控えめに）
- 「ぜひ試してみてください」（読者への提案として）

## 避けること
- 断定的な表現
- 「これが正解」という主張
- 他のアプローチの否定
- 抽象的な説明だけで終わる（具体例がないと伝わりにくい）
- 冗長な説明（ストーリー性は大事だが簡潔に）
- 要点の列挙だけ（読者を引き込むリズムが必要）
```

### tutorial.md - ハンズオン教育

```yaml
---
name: tutorial
description: "ステップバイステップで丁寧に教える"
---

# Tutorial スタイル

## トーン
- 丁寧で親切
- 初心者にも分かりやすく
- 励ましを含める

## 構成のポイント
- ゴールを最初に明示
- 前提条件を明確に
- 各ステップを番号付きで
- 各ステップで「何が起こるか」を説明
- つまづきやすいポイントを先回りで解説
- 完成コードを最後に提示

## 使う表現
- 「まずは〜しましょう」
- 「ここでは〜を行います」
- 「うまくいかない場合は〜を確認してください」
- 「おめでとうございます！」

## 避けること
- 説明なしのコードダンプ
- 「簡単です」という表現（読者を萎縮させる）
- 前提知識の省略
```

### deep-dive.md - 技術深掘り

```yaml
---
name: deep-dive
description: "技術的な詳細を深く掘り下げる"
---

# Deep-Dive スタイル

## トーン
- 専門的で詳細
- 根拠を示す
- 正確さを重視

## 構成のポイント
- 問題の背景を詳しく説明
- 複数のアプローチを比較
- トレードオフを明示
- ベンチマークや数値を含める
- 参考文献を充実させる

## 使う表現
- 「〜の理由は〜です」
- 「〜と比較すると」
- 「内部的には〜が行われています」
- 「ドキュメントによると」

## 避けること
- 根拠のない主張
- 過度な簡略化
- 初心者向けの冗長な説明
```

## Custom Perspective

標準テンプレートに合わない場合は、直接指定も可能:

```
> ideas/20241215_new-feature.md を記事にして
> 観点: 控えめに、個人的な考えとして表現。技術的な詳細より「なぜこう設計したか」を重視
```

この場合、生成された記事の `_meta.perspective_notes` に記録される:

```yaml
_meta:
  perspective: custom
  perspective_notes: |
    控えめに、個人的な考えとして表現。
    技術的な詳細より「なぜこう設計したか」を重視
```

## Creating New Templates

新しい観点テンプレートを追加する場合:

1. `perspectives/` に新しい `.md` ファイルを作成
2. フロントマターに `name` と `description` を記載
3. トーン、構成のポイント、使う表現、避けることを定義

**例: announcement.md（リリース告知向け）**

```yaml
---
name: announcement
description: "新機能やリリースを告知する"
---

# Announcement スタイル

## トーン
- ニュース性を重視
- 簡潔で要点を押さえる
- ワクワク感を伝える

## 構成のポイント
- 最初に「何が新しいか」を端的に
- 主要な変更点を箇条書きで
- アップグレード方法を明記
- 今後の予定も軽く触れる

...
```

---

## Combining Perspectives

複数の観点を組み合わせることも可能:

```
> ideas/20241215_new-lib.md を showcase + tutorial で Zenn 記事を書いて
```

この場合:
- 前半は showcase（製品紹介、何ができるか）
- 後半は tutorial（使い方のステップバイステップ）

---

## Perspective Selection Guide

| 書きたい内容 | 推奨 perspective |
|-------------|------------------|
| 新しいツールを紹介したい | showcase |
| 開発中に考えたことを共有 | personal |
| 使い方を教えたい | tutorial |
| 仕組みを詳しく解説 | deep-dive |
| リリースを告知 | announcement |
| 複数ツールを比較 | deep-dive |
| 失敗談を共有 | personal |
